## What coverage does and does not tell you

- It shows code that **never ran** in any test. It does not show that assertions are meaningful: a line can execute without its result being checked. Mutation testing would measure that and has not been run.
- Tests run against a real PostgreSQL (and Redis), so integration paths count; but external systems (AI providers, proctoring vendor, identity provider, Docker sandbox, ClamAV, S3) are exercised only against fakes, so those adapters can show high coverage and still be wrong about the real service.
- `src/main.ts` and `src/worker.ts` are process entrypoints verified by production-mode smoke boots, not by jest.
